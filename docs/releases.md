# Релизные теги панели

Панель релизится вместе с ботом и использует общую схему версий — **CalVer**:

```
vYYYY.MM.DD          плановый релиз            v2026.07.29
vYYYY.MM.DD.N        хотфикс в тот же день     v2026.07.29.1
```

В релизный день бот и панель тегаются **одной датой**, даже если изменений в панели
мало. Тег docker-образа — это тег git без префикса `v`: `v2026.07.29` даёт
`npvpn/panel:2026.07.29` (и `ghcr.io/npvpn/panel:2026.07.29`).

`__version__` в `app/__init__.py` с тегами не синхронизируется и остаётся как есть.

## GitHub Release

На каждый релизный тег (`vГГГГ.ММ.ДД`, хотфикс `vГГГГ.ММ.ДД.N`) workflow `.github/workflows/release.yml` создаёт GitHub Release:
заголовок — версия без `v`, текст — тело аннотированного тега и список образов. Текст
собирает `scripts/release_notes.sh`.

Тело тега публикуется как есть, поэтому пишем его так, чтобы внешний читатель понял,
что изменилось. У тега без тела в релиз попадает список коммитов от предыдущего тега.

Выпустить релиз для уже существующего тега: Actions → Release → Run workflow, в поле
`tag` — имя тега. Повторный запуск обновляет текст существующего релиза.
Значок «Latest» получает релиз старшего по версии тега; выпуск релиза для более старого тега его не меняет.

Эта схема общая для всех компонентов npvpn; этот документ — её публичное описание.
